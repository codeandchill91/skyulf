## Real defects fixed during acceptance

1. **UC model-version tag names:** dotted `quality_gate.<metric>` was rejected by
   Unity Catalog after a challenger alias call. Tags now use `quality_gate_<metric>`.
   A UC-like rejection check reproduced two failing local lifecycle cases before
   the fix. Original uncertain alias events remain isolated and were not retried.
2. **Nested ensemble diagnostic:** a selected fixed-model CV copy retained
   `tune_base_models`, causing wrapper validation failure. Only the diagnostic
   copy removes this control; saved recipe and selected parameters remain intact.
3. **Automatic halving resource:** a default search axis could duplicate the
   scheduler's selected resource (`n_estimators`). Automatic spaces remove it
   before merging fixed settings. Explicit fixed/searched conflicts still fail.
   Both halving strategies reproduced red and passed after the fix.
4. **Saved-model preflight:** scoring/operator actions expanded the editable
   training recipe without executing its hooks. Default voting composition could
   exceed the grid cap although the trained composition was valid. Training keeps
   full recipe/CV admission; saved-model actions keep structural/config checks
   and use their saved evidence. Four action tests reproduced red, then passed.

## Boundaries and retained evidence

- This tests bounded local pandas/Polars model fitting with real Spark/Delta/UC
  data movement and registry publication. It does not prove Spark-native fitting,
  production-scale performance, every parameter combination or multiclass parity.
- The generated score notebook runs as an ephemeral task in the same submission.
  The persistent two-job child handoff, cron/concurrency and permission boundaries
  were not redeployed or revalidated in this rehearsal.
- Nested CV is a **post-selection diagnostic on a fixed selected model**, not an
  unbiased outer search. Normal search folds are recorded in `tuning.json`; only
  the nested diagnostic has separate `cross_validation.json`.
- SHAP optional dependencies were explicitly installed for this test. Existing
  bounded JSON evidence is tested; opt-in setup/dependency/UI/chart integration
  remains SM-36e. Segmentation remains SM-36d, not implemented or tested here.
- r1 uncertain challenger events remain in their isolated names with no champion
  and no scoring. Their read-only audit is in `sm36_live/failed-alias-audit.json`.
- Scripts, generated projects, raw run/task outputs and hashes are under
  `rehearsals/sm36_live*`; final harness notes are in
  [the r5 README](rehearsals/sm36_live_r5/README.md). These ignored evidence files
  need explicit inclusion if selected for a later commit; nothing was staged here.
